A contagem de livros volta — agora como projeção

🎯 Objetivo

Fechar o arco aberto na fase 04. O campo livros_no_acervo que recusamos volta — com outro dono, outro significado e outro mecanismo.

👨‍💻 O que você digita

  1. autores ganha a coluna livros_no_acervo (a Autoria é dona da tabela, então é decisão dela) — com migração, como a fase 50 ensinou;
  2. Autor carrega o campo, documentado como projeção, não invariante;
  3. ProjecaoDeLivros entra na API pública da Autoria;
  4. o composition root assina o evento e liga uma coisa na outra;
  5. o número atravessa a camada anticorrupção de volta e aparece na busca.

import type { AutorId } from "../../shared/identifiers";
import type { AutorRepository } from "./domain/AutorRepository";

/**
 * A coluna de contagem que evitamos de propósito lá na fase 04 volta aqui —
 * mas com outro dono e outro significado. Não é a verdade sobre o acervo;
 * é uma projeção que a Autoria mantém para si, alimentada por eventos.
 */
export class ProjecaoDeLivros {
  constructor(private readonly autores: AutorRepository) {}

  registrarEntrada(autorId: AutorId): void {
    this.autores.ajustarLivrosNoAcervo(autorId, +1);
  }
}

import { db } from "../../../infrastructure/db";
import { Autor, type TipoDeAutor } from "../domain/Autor";
import type { AutorRepository } from "../domain/AutorRepository";
import type { ConsultaDeAutores, ResumoDoAutor } from "../ConsultaDeAutores";
import { AutorId } from "../../../shared/identifiers";

type AutorRow = {
  id: number;
  nome: string;
  orcid: string | null;
  tipo: string;
  livros_no_acervo: number;
};

function toAutor(row: AutorRow): Autor {
  return new Autor(
    new AutorId(row.id),
    row.nome,
    row.tipo as TipoDeAutor,
    row.livros_no_acervo,
  );
}

export class SqliteAutorRepository
  implements AutorRepository, ConsultaDeAutores
{
  findById(autorId: AutorId): Autor | null {
    const row = db
      .query("SELECT * FROM autores WHERE id = ?")
      .get(autorId.value) as AutorRow | null;

    return row === null ? null : toAutor(row);
  }

  resumo(autorId: AutorId): ResumoDoAutor | null {
    const autor = this.findById(autorId);

    if (autor === null) return null;

    return {
      nome: autor.nome,
      tipo: autor.tipo,
      livrosNoAcervo: autor.livrosNoAcervo,
    };
  }

  ajustarLivrosNoAcervo(autorId: AutorId, delta: number): void {
    db.run(
      "UPDATE autores SET livros_no_acervo = livros_no_acervo + ? WHERE id = ?",
      [delta, autorId.value],
    );
  }

  idsPorNome(termo: string): AutorId[] {
    const rows = db
      .query("SELECT id FROM autores WHERE nome LIKE ?")
      .all(`%${termo}%`) as { id: number }[];

    return rows.map((row) => new AutorId(row.id));
  }
}

Primeiro sobre o banco que já existe, para ver a migração:

bun run start

Depois, do zero, para ver a contagem subir:

terminal
rm -f data/biblioteca.sqlite   # e reinicie o servidor

# banco zerado: a busca ainda não acha nada
curl -w "\n" localhost:3000/livros/9780141439518

# cadastra o primeiro livro de Jane Austen
curl -o /dev/null -s -X POST localhost:3000/livros \
  -H 'Content-Type: application/json' -d '{"isbn":"9780141439518","titulo":"Orgulho e Preconceito","autorId":4}'

# a mesma busca agora traz livrosDoAutor: 1, lido da projeção — sem nenhum JOIN
curl -w "\n" localhost:3000/livros/9780141439518

# segundo livro: a resposta ainda diz 1 porque foi montada antes de o evento chegar
curl -w "\n" -X POST localhost:3000/livros \
  -H 'Content-Type: application/json' -d '{"isbn":"9780141439662","titulo":"Razão e Sensibilidade","autorId":4}'

# a busca seguinte já vê 2: consistência eventual, em escala de milissegundos
curl -w "\n" localhost:3000/livros/Austen

# a projeção gravada em autores: quem a escreveu foi a Autoria, ouvindo o evento do Acervo
sqlite3 data/biblioteca.sqlite "SELECT nome, livros_no_acervo FROM autores;"
resposta
[]
[{"id":1,"numeroRegistro":"2026-000001","isbn":"9780141439518","titulo":"Orgulho e Preconceito","autor":"Jane Austen","livrosDoAutor":1,...}]

A contagem subiu de 0 para 1 e depois para 2, e nenhum JOIN foi escrito: o número está gravado em autores, e quem o escreveu foi a Autoria, ao receber um evento que o Acervo publicou sem saber quem escutava.

E repare no que o Buscar Livro ganhou sem mudar uma linha: quem procura por "Austen" agora vê quantos livros daquela autora a biblioteca tem. Foi o arco inteiro do documento — a coluna recusada na fase 04, o evento da fase 51, a projeção desta fase — para responder a pergunta mais banal que um usuário de biblioteca faz.

Repare também na terceira linha, a resposta do segundo POST: ela diz livrosDoAutor: 1, e o livro que ela descreve é o segundo de Jane Austen. Não é bug — é o mecanismo à mostra. O caso de uso leu a autora antes de gravar e de publicar; o evento incrementou a projeção depois; a resposta foi montada com a leitura antiga. Consistência eventual, em escala de milissegundos, no mesmo processo.
