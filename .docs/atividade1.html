Atividade 1 — Cadastrar Autor

Uma feature nova, do zero, atravessando todas as camadas de uma fatia vertical: apresentação, aplicação, domínio e infraestrutura, mais o composition root e os testes. Você parte do código ao fim da fase 53 e entrega quinze arquivos depois — sendo oito novos e sete editados.

O sistema já sabe cadastrar e buscar livros. O que ele não sabe é cadastrar um autor: a base de autores entra por um seed fixo, e o módulo autoria é o único sem pasta features/. Esta atividade abre a primeira fatia dele.

00

Antes de começar

O módulo autoria é o único do sistema que não tem pasta features/. Ele existe porque é dono de um dado — a tabela autores —, não porque executa uma operação. Hoje a base de autores entra por um seed fixo no schema.ts: quatro nomes, gravados na criação da tabela. Não há como cadastrar um autor novo pela API.

Nesta atividade você abre a primeira fatia vertical da Autoria. Ao terminar, a árvore do módulo terá a mesma forma que o Acervo já tem — e você terá tocado todas as camadas: apresentação, aplicação, domínio e infraestrutura, mais o composition root e os testes.

Regras de negócio a implementar
  1. RN1 — nome é obrigatório; tipo deve ser literatura ou didatico.
  2. RN2 — o ORCID é opcional, mas se vier tem de ser válido: 16 caracteres com dígito verificador ISO 7064 MOD 11-2 (o último pode ser X).
  3. RN3 — o mesmo ORCID não entra duas vezes.
  4. RN4 — o mesmo nome não entra duas vezes, ignorando caixa e espaços nas pontas. Quem decide o que é “o mesmo autor” é a entidade, não o SQL.

Cada regra cai numa camada diferente de propósito. Preste atenção em onde cada uma mora — é isso que a atividade está avaliando, mais do que o código funcionar.

🌳 O ponto de partida

01

Domínio · o value object Orcid

Comece pelo dado mais interno. O ORCID é o identificador internacional de pesquisadores, publicado em quatro grupos de quatro caracteres — 0000-0002-1825-0097. Os 15 primeiros são dígitos; o 16º é um verificador que pode ser X.

Ele é o irmão do Isbn do Acervo: mesma ideia, mesmo contrato. Um valor malformado não pode existir — o construtor recusa. E, como no Isbn, há um isValid estático para quem precisa perguntar antes de construir.

Crie src/modules/autoria/domain/Orcid.ts:

typescript
import { InvalidValue } from "../../../shared/domain-errors";

export class Orcid {
  readonly value: string;

  constructor(raw: string) {
    if (!Orcid.isValid(raw)) {
      throw new InvalidValue(`ORCID inválido: ${raw}`);
    }

    this.value = Orcid.formatar(Orcid.normalizar(raw));
  }

  /**
   * Perguntar antes de construir — o mesmo contrato do Isbn. Quem cadastra
   * exige um ORCID válido; quem apenas consulta pode querer saber se o que
   * foi digitado é um ORCID sem que isso vire erro.
   */
  static isValid(raw: string): boolean {
    const normalizado = Orcid.normalizar(raw);

    return (
      /^[0-9]{15}[0-9X]$/.test(normalizado) && Orcid.digitoConfere(normalizado)
    );
  }

  /**
   * ISO 7064 MOD 11-2: acumula (total + dígito) * 2 nos 15 primeiros
   * caracteres; o 16º é o que fecha a conta — e pode ser X, que vale 10.
   */
  private static digitoConfere(orcid: string): boolean {
    let total = 0;

    for (let i = 0; i < 15; i++) {
      total = (total + Number(orcid[i]!)) * 2;
    }

    const resto = total % 11;
    const calculado = (12 - resto) % 11;

    return (calculado === 10 ? "X" : String(calculado)) === orcid[15];
  }

  private static normalizar(raw: string): string {
    return raw.replace(/[^0-9Xx]/g, "").toUpperCase();
  }

  /** O ORCID é publicado em grupos de quatro; guardamos como é publicado. */
  private static formatar(digitos: string): string {
    return digitos.match(/.{4}/g)!.join("-");
  }

  equals(other: Orcid): boolean {
    return this.value === other.value;
  }

  toString(): string {
    return this.value;
  }
}
Por que aqui? Um ORCID inválido não é um problema de HTTP nem de banco — é um valor que não existe no mundo. Colocar essa checagem na rota faria a mesma regra ter de ser repetida na importação em lote, no seed e em qualquer outro caminho de entrada. No domínio, ela vale para todos.
02

Domínio · a entidade Autor ganha comportamento

Hoje o Autor é um registro passivo: um construtor e quatro campos. Ele precisa de três coisas.

Primeira: nascer por uma fábrica, Autor.cadastrar, como o Livro.catalogar do Acervo. É ela que recusa um tipo fora do vocabulário do domínio.

Segunda: aceitar identidade depois, com withId. Quem atribui o id é a persistência — e a entidade aceita isso sem virar mutável. Por isso o campo id passa a ser AutorId | null.

Terceira: decidir o que é “o mesmo autor”, com mesmoNomeQue. Essa é a RN4, e ela é uma decisão de negócio — não um lower() perdido numa query.

Substitua src/modules/autoria/domain/Autor.ts:

typescript
import { InvalidValue } from "../../../shared/domain-errors";
import type { AutorId } from "../../../shared/identifiers";
import type { Orcid } from "./Orcid";

export type TipoDeAutor = "literatura" | "didatico";

export class NomeDeAutorVazio extends InvalidValue {
  constructor() {
    super("O nome do autor é obrigatório");
  }
}

export class TipoDeAutorDesconhecido extends InvalidValue {
  constructor(tipo: string) {
    super(`Tipo de autor desconhecido: ${tipo}`);
  }
}

export class Autor {
  constructor(
    readonly id: AutorId | null,
    readonly nome: string,
    readonly tipo: TipoDeAutor,
    /**
     * PROJEÇÃO, não invariante. Este número é mantido por eventos vindos do
     * Acervo e pode divergir da verdade. Nenhuma regra de negócio deste
     * módulo — nem de nenhum outro — pode decidir com base nele.
     */
    readonly livrosNoAcervo: number,
    readonly orcid: Orcid | null = null,
  ) {
    if (Autor.normalizar(nome) === "") {
      throw new NomeDeAutorVazio();
    }
  }

  /** Um autor nasce por aqui — e nasce válido. */
  static cadastrar(nome: string, tipo: string, orcid: Orcid | null): Autor {
    if (tipo !== "literatura" && tipo !== "didatico") {
      throw new TipoDeAutorDesconhecido(tipo);
    }

    return new Autor(null, nome.trim(), tipo, 0, orcid);
  }

  /** Quem atribui a identidade é a persistência; a entidade aceita sem virar mutável. */
  withId(id: AutorId): Autor {
    return new Autor(id, this.nome, this.tipo, this.livrosNoAcervo, this.orcid);
  }

  /** O que conta como "o mesmo autor" é decisão do negócio, não do SQL. */
  mesmoNomeQue(outro: string): boolean {
    return Autor.normalizar(this.nome) === Autor.normalizar(outro);
  }

  private static normalizar(nome: string): string {
    return nome.trim().toLowerCase();
  }
}
Repare que o comentário sobre livrosNoAcervo ser projeção, não invariante continua ali, intacto. Ele não é decoração: é o que impede alguém de usar esse número para decidir alguma coisa. Sua fábrica nasce com 0 e nunca mais mexe nele.
03

Domínio · a porta AutorRepository cresce

A porta é declarada no domínio e implementada na infraestrutura — o domínio diz o que precisa, nunca como se faz. Para cadastrar, o caso de uso precisa de três perguntas novas.

Note o findByNomeSemelhante: ele devolve candidatos, não uma resposta. A decisão de igualdade fica na entidade, via mesmoNomeQue. É o mesmo desenho que o Acervo usa em findByAutorId(...).some(livro => livro.mesmoTituloQue(...)).

Substitua src/modules/autoria/domain/AutorRepository.ts:

typescript
import type { Autor } from "./Autor";
import type { Orcid } from "./Orcid";
import type { AutorId } from "../../../shared/identifiers";

export interface AutorRepository {
  findById(autorId: AutorId): Autor | null;

  /** A persistência atribui a identidade e devolve o autor já identificado. */
  insert(autor: Autor): Autor;

  findByOrcid(orcid: Orcid): Autor | null;

  /** Devolve candidatos; quem decide se é "o mesmo autor" é a entidade. */
  findByNomeSemelhante(nome: string): Autor[];

  /** Escrita da projeção. Só a própria Autoria chama isto. */
  ajustarLivrosNoAcervo(autorId: AutorId, delta: number): void;
}
Armadilha comum: seria mais curto declarar existeComNome(nome): boolean e resolver tudo num SELECT ... WHERE lower(nome) = lower(?). Mais curto e errado: a regra de igualdade migraria para o SQL, ficaria invisível para os testes de unidade e teria de ser reescrita ao trocar de banco.
04

Aplicação · validação da entrada

A fronteira HTTP entrega unknown. Antes de qualquer regra, o corpo precisa virar um tipo. Esse é o papel do input.ts da fatia — e ele usa os mesmos helpers compartilhados que o cadastro de livro usa, então mensagens de erro saem no mesmo formato.

O orcid é o único campo opcional: ausente vira null; presente é exigido como texto não vazio. Repare que aqui não se valida o formato do ORCID — isso é do domínio, e você já fez.

Crie src/modules/autoria/features/cadastrar-autor/input.ts:

typescript
import { getBodyAsObject, getFieldAsText } from "../../../../shared/validation";

export type NovoAutor = {
  nome: string;
  tipo: string;
  orcid: string | null;
};

export function parseNovoAutor(body: unknown): NovoAutor {
  const data = getBodyAsObject(body);

  return {
    nome: getFieldAsText(data, "nome"),
    tipo: getFieldAsText(data, "tipo"),
    orcid: data.orcid === undefined ? null : getFieldAsText(data, "orcid"),
  };
}
05

Aplicação · o caso de uso CadastrarAutor

O caso de uso é o maestro: ele não sabe o que é HTTP, não sabe o que é SQLite, e não implementa regra nenhuma sozinho. Ele ordena as perguntas e deixa cada resposta com quem é dono dela.

Leia o corpo do execute como uma frase: monta o ORCID (o domínio valida), pergunta se o ORCID já existe (RN3), pergunta se o nome já existe (RN4, decidida pela entidade), manda a entidade nascer (RN1) e grava. Cinco linhas de regra, cada uma apontando para outra camada.

Crie src/modules/autoria/features/cadastrar-autor/CadastrarAutor.ts:

typescript
import { Autor } from "../../domain/Autor";
import type { AutorRepository } from "../../domain/AutorRepository";
import { Orcid } from "../../domain/Orcid";
import { RuleConflict } from "../../../../shared/errors";
import type { NovoAutor } from "./input";
import { autorToJson, type AutorJson } from "../../output";

export class CadastrarAutor {
  constructor(private readonly autores: AutorRepository) {}

  execute(input: NovoAutor): AutorJson {
    const orcid = input.orcid === null ? null : new Orcid(input.orcid);

    if (orcid !== null && this.autores.findByOrcid(orcid)) {
      throw new RuleConflict("Autor já cadastrado com este ORCID");
    }

    const homonimo = this.autores
      .findByNomeSemelhante(input.nome)
      .some((autor) => autor.mesmoNomeQue(input.nome));

    if (homonimo) {
      throw new RuleConflict("Já existe um autor com este nome");
    }

    const autor = this.autores.insert(
      Autor.cadastrar(input.nome, input.tipo, orcid),
    );

    return autorToJson(autor);
  }
}
O construtor recebe a porta, não o adapter: AutorRepository, não SqliteAutorRepository. É isso que vai permitir testar este arquivo sem banco nenhum, no passo 12.

Aplicação · a saída

A entidade não vira JSON sozinha. Se ela virasse, o formato da resposta HTTP passaria a ser decidido dentro do domínio — e qualquer renomeação de campo interno viraria uma quebra de contrato para quem consome a API.

07

Apresentação · a rota e o registro do módulo

A rota é a camada mais fina do sistema e tem exatamente um trabalho: traduzir HTTP em chamada de caso de uso, e o retorno em resposta. Nenhum if de regra pode aparecer aqui. Erro nenhum é tratado nela — quem traduz exceção em status é o onError do servidor, que já existe.

Crie src/modules/autoria/features/cadastrar-autor/route.ts:

typescript
import type { Hono } from "hono";
import type { UseCases } from "../../../../composition";
import { parseNovoAutor } from "./input";

export function register(routes: Hono, useCases: UseCases): void {
  routes.post("/autores", async (contexto) => {
    const autor = useCases.cadastrarAutor.execute(
      parseNovoAutor(await contexto.req.json()),
    );

    contexto.header("Location", `/autores/${autor.id}`);

    return contexto.json(autor, 201);
  });
}

08

Infraestrutura · o adapter implementa a porta

Agora, e só agora, aparece SQL. O SqliteAutorRepository é o único arquivo do módulo que sabe que existe um banco — e ele implementa o contrato que o domínio declarou, sem acrescentar regra nenhuma.

1. Acrescente o import do value object no topo de src/modules/autoria/infrastructure/SqliteAutorRepository.ts:

typescript
import { Orcid } from "../domain/Orcid";

2. A linha vira uma entidade completa: o orcid gravado precisa voltar como value object. Substitua a função toAutor:

typescript
function toAutor(row: AutorRow): Autor {
  return new Autor(
    new AutorId(row.id),
    row.nome,
    row.tipo as TipoDeAutor,
    row.livros_no_acervo,
    row.orcid === null ? null : new Orcid(row.orcid),
  );
}

3. Acrescente os três métodos da porta dentro da classe, antes de resumo:

typescript
  insert(autor: Autor): Autor {
    const result = db.run(
      "INSERT INTO autores (nome, orcid, tipo) VALUES (?, ?, ?)",
      [autor.nome, autor.orcid?.value ?? null, autor.tipo],
    );

    return autor.withId(new AutorId(result.lastInsertRowid as number));
  }

  findByOrcid(orcid: Orcid): Autor | null {
    const row = db
      .query("SELECT * FROM autores WHERE orcid = ?")
      .get(orcid.value) as AutorRow | null;

    return row === null ? null : toAutor(row);
  }

  findByNomeSemelhante(nome: string): Autor[] {
    const rows = db
      .query("SELECT * FROM autores WHERE nome LIKE ?")
      .all(`%${nome.trim()}%`) as AutorRow[];

    return rows.map(toAutor);
  }
Por que insert devolve o autor? Porque a identidade nasce no banco. O lastInsertRowid volta para dentro da entidade por withId — e o caso de uso recebe um Autor já identificado, sem nunca ter visto um rowid.

Composição · o único lugar que conhece os dois lados

O composition root é o único arquivo do sistema que sabe, ao mesmo tempo, que existem casos de uso e que existe SQLite. É aqui que a porta encontra o adapter.

O SqliteAutorRepository já era instanciado — ele alimenta a projeção de livros. Você só passa a mesma instância para o caso de uso novo.

Substitua src/composition.ts:

typescript
import { AutoriaComoConsulta } from "./adapters/AutoriaComoConsulta";
import {
  BuscarLivro,
  CadastrarLivro,
  type LivroCatalogado,
  SqliteLivroRepository,
} from "./modules/acervo";
import {
  CadastrarAutor,
  ProjecaoDeLivros,
  SqliteAutorRepository,
} from "./modules/autoria";
import type { Clock } from "./shared/Clock";
import { EventBus } from "./shared/EventBus";
import { AutorId } from "./shared/identifiers";

export type UseCases = {
  cadastrarLivro: CadastrarLivro;
  buscarLivro: BuscarLivro;
  cadastrarAutor: CadastrarAutor;
};

/**
 * Composition root: este é o ÚNICO lugar do sistema que sabe, ao mesmo tempo,
 * que existem casos de uso e que existe SQLite. Trocar de banco é trocar as
 * duas linhas de `new Sqlite...` daqui.
 */
export function buildUseCases(now: Clock = () => new Date()): UseCases {
  const livros = new SqliteLivroRepository();
  const autores = new SqliteAutorRepository();
  const autoria = new AutoriaComoConsulta(autores);
  const bus = new EventBus();
  const projecao = new ProjecaoDeLivros(autores);

  bus.subscribe<LivroCatalogado>("LivroCatalogado", (event) =>
    projecao.registrarEntrada(new AutorId(event.autorId)),
  );

  return {
    cadastrarLivro: new CadastrarLivro(livros, autoria, now, bus),
    buscarLivro: new BuscarLivro(livros, autoria),
    cadastrarAutor: new CadastrarAutor(autores),
  };
}
11

Apresentação · o servidor registra as rotas da Autoria

Uma linha de import e uma de registro. O errorResponse que já existe cuida da tradução: InvalidValue e InvalidInput viram 400, NotFound vira 404, RuleConflict e DomainError viram 409. Você não escreve um status sequer.

Substitua src/server.ts:

typescript
import { Hono } from "hono";
import type { UseCases } from "./composition";
import { DomainError, InvalidValue } from "./shared/domain-errors";
import { registerRoutes as registerAcervo } from "./modules/acervo";
import { registerRoutes as registerAutoria } from "./modules/autoria";
import { InvalidInput, NotFound, RuleConflict } from "./shared/errors";

function errorResponse(error: unknown): Response {
  if (error instanceof InvalidInput || error instanceof InvalidValue) {
    return Response.json({ error: error.message }, { status: 400 });
  }

  if (error instanceof NotFound) {
    return Response.json({ error: error.message }, { status: 404 });
  }

  if (error instanceof RuleConflict || error instanceof DomainError) {
    return Response.json({ error: error.message }, { status: 409 });
  }

  console.error(error);

  return Response.json({ error: "Erro interno" }, { status: 500 });
}

export function createServer(useCases: UseCases, porta = Number(process.env.PORT ?? 3000)) {
  const app = new Hono();

  app.get("/", (contexto) => contexto.json({ message: "API da Biblioteca" }));

  registerAutoria(app, useCases);
  registerAcervo(app, useCases);

  app.notFound((contexto) =>
    contexto.json({ error: "Recurso não encontrado" }, 404),
  );

  app.onError((error) => errorResponse(error));

  return Bun.serve({ port: porta, fetch: app.fetch });
}
Este é o momento de olhar para trás: as suas quatro regras de negócio produzem 400, 400, 409 e 409 — e nenhum desses números aparece no código que você escreveu. Eles saem do tipo do erro que cada camada lança.

Prova · a regra testada sem HTTP e sem banco

Se o desenho estiver certo, o caso de uso roda em memória. Primeiro o dublê: um repositório que implementa a mesma porta com um array.

1. Acrescente os imports no topo de tests/doubles.ts:

typescript
import type { Autor } from "../src/modules/autoria/domain/Autor";
import type { AutorRepository } from "../src/modules/autoria/domain/AutorRepository";
import type { Orcid } from "../src/modules/autoria/domain/Orcid";

2. E a classe, no fim do mesmo arquivo:

typescript
export class InMemoryAutorRepository implements AutorRepository {
  private items: Autor[] = [];
  private nextId = 1;

  insert(autor: Autor): Autor {
    const salvo = autor.withId(new AutorId(this.nextId++));
    this.items.push(salvo);

    return salvo;
  }

  findById(autorId: AutorId): Autor | null {
    return this.items.find((item) => item.id?.equals(autorId)) ?? null;
  }

  findByOrcid(orcid: Orcid): Autor | null {
    return this.items.find((item) => item.orcid?.equals(orcid)) ?? null;
  }

  findByNomeSemelhante(nome: string): Autor[] {
    const alvo = nome.trim().toLowerCase();

    return this.items.filter((item) => item.nome.toLowerCase().includes(alvo));
  }

  ajustarLivrosNoAcervo(): void {
    /* a projeção não participa deste caso de uso */
  }
}
