Atividade 3 — Consultar autor e suas obras

Uma consulta que atravessa a fronteira entre os módulos no sentido contrário ao da fase 49: agora é a Autoria que precisa de dados do Acervo. Você parte do código ao fim da atividade 2 e entrega quatorze arquivos depois — sendo sete novos e sete editados.

Nenhum módulo vai importar o outro. A Autoria declara o que precisa, o Acervo publica o que oferece, e um adapter no meio traduz um vocabulário no outro.

diagrama
camadas e artefatos

Leia o diagrama de cima para baixo: a requisição entra pela Autoria, desce até a porta que ela declarou e só então cruza a fronteira — por um adapter que não pertence a nenhum dos dois módulos — até o contrato que o Acervo publica. Cada caixa é um arquivo que você vai criar ou editar.

00

Antes de começar

A atividade 1 terminou com um cadastro que devolve Location: /autores/5 — um endereço que não existe. Esta atividade faz ele existir: GET /autores/:id devolve o autor e as obras dele que estão na estante.

O pedido é simples. O problema está no desenho. O autor mora na Autoria; os livros moram no Acervo; e, desde a fase 50, cada módulo é dono das suas tabelas — a Autoria não pode fazer SELECT em livros, e o bun run verificar reprova se tentar.

Há três jeitos de resolver, e vale conhecer os três antes de escrever uma linha:

DesenhoComoCusto
A Autoria importa o Acervoo caso de uso faz import ... from "../../../acervo" e chama o repositório de livrosO verificar aceita — é a API pública. Mas o Acervo já depende da Autoria (pela ConsultaDeAutoria), e os dois módulos ficam amarrados nos dois sentidos.
Projeção de títulosa Autoria guarda os títulos, alimentada por LivroCatalogado e LivroBaixadoNenhuma dependência nova, mas mais uma cópia que pode divergir, mais uma tabela e mais uma migração.
Porta e camada anticorrupçãoa Autoria declara o que precisa, no vocabulário dela; um adapter fora dos módulos traduz a partir de um contrato publicado pelo AcervoDois contratos pequenos e um adapter. Nenhum módulo importa o outro.

Esta atividade segue o terceiro — é o desenho da fase 49, espelhado. O primeiro volta como pergunta no fim.

Regras da consulta
  1. RC1 — o id tem de ser um inteiro positivo.
  2. RC2 — autor que não existe devolve “não encontrado”.
  3. RC3 — as obras são só as que estão no acervo. Quem decide o que está no acervo é o Acervo, com o Livro.estaNoAcervo da atividade 2.
  4. RC4 — a resposta mostra lado a lado livrosNoAcervo, a projeção da Autoria, e obras, o que o Acervo diz agora. Os dois podem divergir, e a consulta não “conserta” nenhum.

Não há regra de negócio nova aqui — é uma consulta. O que a atividade avalia é por onde a informação passa.

01

Domínio · a porta ConsultaDeAcervo

Comece por quem precisa. A Autoria declara, no domínio dela, o que quer saber do acervo — com as palavras dela. Para a Autoria, um autor tem obras: título e ISBN. Número de registro, data de catalogação e baixa são detalhes de patrimônio que não lhe dizem respeito.

Crie src/modules/autoria/domain/ConsultaDeAcervo.ts:

typescript
import type { AutorId } from "../../../shared/identifiers";

/**
 * Vocabulário do módulo Autoria. O Acervo fala em "livro", com número de
 * registro, data de catalogação e baixa; aqui nada disso interessa —
 * interessa a OBRA que o autor tem na estante.
 */
export type Obra = {
  titulo: string;
  isbn: string;
};

/** Port de saída: tudo o que a Autoria precisa saber sobre o acervo. */
export interface ConsultaDeAcervo {
  obrasDe(autorId: AutorId): Obra[];
}
Por que no domínio da Autoria? É a inversão de dependência da fase 38, aplicada entre módulos: quem precisa do serviço declara o contrato. Se a Autoria usasse aqui um tipo do Acervo, qualquer renomeação lá dentro quebraria o domínio de cá — e a Autoria não teria como testar a consulta sem o Acervo existir.
02

03

Aplicação · o caso de uso ConsultarAutor

Duas perguntas, cada uma para o seu dono: o autor, ao repositório da própria Autoria (RC2); as obras, à porta (RC3). O caso de uso não soma, não filtra, não compara — e não sabe que existe um módulo chamado Acervo.

Crie src/modules/autoria/features/consultar-autor/ConsultarAutor.ts:

typescript
import { NotFound } from "../../../../shared/errors";
import { AutorId } from "../../../../shared/identifiers";
import type { AutorRepository } from "../../domain/AutorRepository";
import type { ConsultaDeAcervo } from "../../domain/ConsultaDeAcervo";
import { autorComObrasToJson, type AutorComObrasJson } from "../../output";

export class ConsultarAutor {
  constructor(
    private readonly autores: AutorRepository,
    private readonly acervo: ConsultaDeAcervo,
  ) {}

  execute(id: number): AutorComObrasJson {
    const autorId = new AutorId(id);

    const autor = this.autores.findById(autorId);

    if (!autor) {
      throw new NotFound("Autor não encontrado");
    }

    // o autor é dado desta casa; as obras, o Acervo é quem sabe
    return autorComObrasToJson(autor, this.acervo.obrasDe(autorId));
  }
}
O construtor recebe duas portas: AutorRepository e ConsultaDeAcervo. No teste do passo 12, as duas viram dublês em memória, e a consulta roda sem banco e sem uma linha do Acervo carregada.
04

Aplicação · a saída

A resposta estende o AutorJson da atividade 1 com a lista de obras. Repare que ela copia campo a campo em vez de devolver a Obra como veio: o formato do JSON é contrato com quem consome a API; o formato da porta é contrato entre módulos. Um não deve arrastar o outro quando mudar.

Substitua src/modules/autoria/output.ts — as linhas em destaque são as que mudam:

Apresentação · a rota e o registro no módulo

Um GET sem corpo, status 200 sem ninguém escrever, nenhum if.

Crie src/modules/autoria/features/consultar-autor/route.ts:

typescript
import type { Hono } from "hono";
import type { UseCases } from "../../../../composition";
import { parseAutorId } from "./input";

export function register(routes: Hono, useCases: UseCases): void {

06

Acervo · o contrato publicado ConsultaDeLivros

Agora o outro lado. O Acervo não sabe que a Autoria vai perguntar — e não vai saber. Ele publica um contrato de leitura no vocabulário dele, como a Autoria fez com a ConsultaDeAutores na fase 49.

Crie src/modules/acervo/ConsultaDeLivros.ts:

typescript
import type { AutorId } from "../../shared/identifiers";

export type ResumoDoLivro = {
  numeroRegistro: string;
  isbn: string;
  titulo: string;
};

/** Contrato de leitura publicado pelo Acervo, no vocabulário do Acervo. */
export interface ConsultaDeLivros {
  /** Só o que está na estante: quem decide o que é "no acervo" é o Livro. */
  noAcervoDoAutor(autorId: AutorId): ResumoDoLivro[];
}

O arquivo fica na raiz do módulo, ao lado do index.ts, e não em domain/: é contrato público, feito para ser lido de fora — não é regra interna. A ConsultaDeAutores da Autoria está no mesmo lugar, pelo mesmo motivo.

07

Infraestrutura · o adapter SQLite implementa o contrato

O SqliteLivroRepository passa a implementar duas interfaces — a porta interna e o contrato publicado —, como o SqliteAutorRepository já faz. E repare no que ele não faz: nenhum baixa_em IS NULL. Ele reaproveita o findByAutorId e pergunta a cada livro se ele está no acervo.

Substitua src/modules/acervo/infrastructure/SqliteLivroRepository.ts — as linhas em destaque são as que mudam:

typescript
import { db } from "../../../infrastructure/db";
import { LivroId, AutorId } from "../../../shared/identifiers";
import type { ConsultaDeLivros, ResumoDoLivro } from "../ConsultaDeLivros";
import { Baixa, type MotivoDeBaixa } from "../domain/Baixa";
import { Isbn } from "../domain/Isbn";
import { Livro } from "../domain/Livro";
import type { LivroRepository } from "../domain/LivroRepository";
import { NumeroRegistro } from "../domain/NumeroRegistro";

type LivroRow = {
  id: number;
  numero_registro: string;
  isbn: string;
  titulo: string;
  autor_id: number;
  data_catalogacao: string;
  baixa_motivo: string | null;
  baixa_em: string | null;
};

function toLivro(row: LivroRow): Livro {
  return new Livro(
    new LivroId(row.id),
    new NumeroRegistro(row.numero_registro),
    new Isbn(row.isbn),
    row.titulo,
    new AutorId(row.autor_id),
    row.data_catalogacao,
    row.baixa_em === null
      ? null
      : new Baixa(row.baixa_motivo as MotivoDeBaixa, row.baixa_em),
  );
}

function toResumo(livro: Livro): ResumoDoLivro {
  return {
    numeroRegistro: livro.numeroRegistro.value,
    isbn: livro.isbn.value,
    titulo: livro.titulo,
  };
}

export class SqliteLivroRepository
  implements LivroRepository, ConsultaDeLivros
{
  contarCatalogadosNoAno(ano: string): number {
    const row = db
      .query(
        `SELECT COUNT(*) AS total FROM livros
          WHERE data_catalogacao LIKE ?`,
      )
      .get(`${ano}%`) as { total: number };

    return row.total;
  }

  insert(livro: Livro): Livro {
    const result = db.run(
      `INSERT INTO livros (numero_registro, isbn, titulo, autor_id, data_catalogacao)
       VALUES (?, ?, ?, ?, ?)`,
      [
        livro.numeroRegistro.value,
        livro.isbn.value,
        livro.titulo,
        livro.autorId.value,
        livro.dataCatalogacao,
      ],
    );

    return livro.withId(new LivroId(Number(result.lastInsertRowid)));
  }

  findByIsbn(isbn: Isbn): Livro | null {
    const row = db
      .query("SELECT * FROM livros WHERE isbn = ?")
      .get(isbn.value) as LivroRow | null;

    return row === null ? null : toLivro(row);
  }

  findByNumeroRegistro(numero: NumeroRegistro): Livro | null {
    const row = db
      .query("SELECT * FROM livros WHERE numero_registro = ?")
      .get(numero.value) as LivroRow | null;

    return row === null ? null : toLivro(row);
  }

  findByAutorId(autorId: AutorId): Livro[] {
    const rows = db
      .query("SELECT * FROM livros WHERE autor_id = ?")
      .all(autorId.value) as LivroRow[];

    return rows.map(toLivro);
  }

  searchByTitulo(termo: string): Livro[] {
    const rows = db
      .query("SELECT * FROM livros WHERE titulo LIKE ?")
      .all(`%${termo}%`) as LivroRow[];

    return rows.map(toLivro);
  }

  findByAutorIds(autorIds: AutorId[]): Livro[] {
    if (autorIds.length === 0) return [];

    const placeholders = autorIds.map(() => "?").join(", ");
    const rows = db
      .query(`SELECT * FROM livros WHERE autor_id IN (${placeholders})`)
      .all(...autorIds.map((autorId) => autorId.value)) as LivroRow[];

    return rows.map(toLivro);
  }

  noAcervoDoAutor(autorId: AutorId): ResumoDoLivro[] {
    return this.findByAutorId(autorId)
      .filter((livro) => livro.estaNoAcervo())
      .map(toResumo);
  }

  registrarBaixa(livro: Livro): void {
    db.run("UPDATE livros SET baixa_motivo = ?, baixa_em = ? WHERE id = ?", [
      livro.baixa!.motivo,
      livro.baixa!.em,
      livro.id!.value,
    ]);
  }
}
