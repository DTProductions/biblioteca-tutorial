Atividade 2 — Dar baixa em livro

Uma operação que muda o estado de um livro que já existe — e que precisa avisar outro módulo. Você parte do código ao fim da atividade 1 e entrega dezessete arquivos depois — sendo cinco novos e doze editados.

A atividade 1 abriu a primeira fatia da Autoria. Esta volta ao Acervo para abrir a terceira: uma fatia que não cria nada, publica um evento e faz a projeção da fase 52 andar para trás.

00

Antes de começar

Até aqui, todo livro que entrou no acervo ficou nele para sempre. O sistema sabe catalogar, mas não sabe tirar — e a biblioteca tira livros o tempo todo.

Livro some, livro estraga, livro a gente doa para outra biblioteca. Hoje, quando isso acontece, ele continua no sistema como se estivesse na estante — e aí a política de aquisição trava: a Austen já tem cinco, não entra mais nenhum, mesmo que dois estejam no lixo.

Eu preciso dar baixa. Pelo número de registro, que é o que está na etiqueta. E só três motivos: extravio, dano ou doação — nada de campo livre, senão cada um escreve uma coisa.

E não apaga, pelo amor de Deus. O número de registro é patrimônio: se o livro saiu, a ficha dele fica, com o motivo e a data.

— Diretora da biblioteca, numa segunda reunião

Regras de negócio a implementar
  1. RN1 — o motivo é obrigatório e tem de ser extravio, dano ou doacao.
  2. RN2 — o livro é identificado pelo número de registro: malformado é valor inválido; bem formado, mas inexistente, é “não encontrado”.
  3. RN3 — a data da baixa é a do servidor, como a de catalogação (RF06).
  4. RN4 — um livro sai do acervo uma vez só.
  5. RN5 — livro baixado não conta no limite por autor (RF05) nem impede o mesmo título de voltar (RF09). O ISBN dele continua reservado (RF08).
  6. RN6 — a baixa é anunciada por um evento, e a Autoria desconta o livro da projeção livrosNoAcervo.
Por que “não apaga” é regra, e não capricho: o RF07 gera o número de registro contando quantos livros foram catalogados no ano (contarCatalogadosNoAno). Um DELETE faria essa contagem voltar, e o próximo livro nasceria com um número que já está numa etiqueta — e que o UNIQUE da coluna recusaria com um erro 500.

A atividade 1 abriu uma fatia que cria. Esta abre uma fatia que muda o estado de uma entidade, reescreve uma regra antiga sem duplicá-la e avisa outro módulo sem conhecê-lo. Preste atenção em onde cada uma dessas três coisas mora.

01

Domínio · o value object Baixa

Comece pelo dado mais interno, como na atividade 1. Uma baixa tem duas partes — o motivo e a data — e uma não existe sem a outra. Se virassem dois campos soltos na entidade, nada impediria um livro com motivo e sem data. Juntos num value object, esse estado meio preenchido deixa de ser representável.

O motivo é um vocabulário fechado (RN1), e quem o recusa é a fábrica Baixa.registrar — o mesmo papel que o Autor.cadastrar faz com o tipo de autor. A data entra como parâmetro: o domínio não chama new Date() sozinho (RN3), pelo mesmo motivo que levou o Clock a existir.

Crie src/modules/acervo/domain/Baixa.ts:

typescript
import { InvalidValue } from "../../../shared/domain-errors";
import { toIso } from "./Livro";

export type MotivoDeBaixa = "extravio" | "dano" | "doacao";

const MOTIVOS: readonly string[] = ["extravio", "dano", "doacao"];

export class MotivoDeBaixaDesconhecido extends InvalidValue {
  constructor(motivo: string) {
    super(`Motivo de baixa desconhecido: ${motivo}`);
  }
}

/**
 * Motivo e data andam juntos: não existe baixa sem um dos dois. Por isso são
 * um único value object, e não duas colunas soltas que podem ficar meio
 * preenchidas.
 */
export class Baixa {
  constructor(
    readonly motivo: MotivoDeBaixa,
    readonly em: string,
  ) {}

  /** A baixa nasce por aqui — com um motivo do vocabulário e a data de hoje. */
  static registrar(motivo: string, hoje: Date): Baixa {
    if (!MOTIVOS.includes(motivo)) {
      throw new MotivoDeBaixaDesconhecido(motivo);
    }

    return new Baixa(motivo as MotivoDeBaixa, toIso(hoje));
  }
}
Por que o construtor não valida? Porque há dois caminhos de entrada. registrar é o caminho do negócio: recebe texto do mundo e confere. O construtor é o caminho da persistência: o adapter reconstrói uma baixa que já foi conferida quando entrou. É a mesma divisão entre Livro.catalogar, que calcula número e data, e o new Livro(...) do toLivro, que só remonta.
02

Domínio · o Livro aprende a sair do acervo

O Livro precisa de três coisas.

Primeira: o campo baixa, do tipo Baixa | null, como último parâmetro do construtor e com null como padrão. Assim nenhuma chamada existente de new Livro(...) quebra.

Segunda: darBaixa, que devolve outro livro, já baixado — a entidade continua imutável, como no withId — e recusa um livro que já saiu (RN4).

Terceira: estaNoAcervo. Parece pouco — é uma comparação com null —, mas é a resposta a uma pergunta de negócio da qual duas regras antigas passam a depender (RN5). Uma pergunta assim precisa de nome e de dono.

03

Domínio · a porta LivroRepository muda

Duas assinaturas entram e uma sai.

Entram findByNumeroRegistro, porque o caso de uso precisa achar o livro pela etiqueta (RN2), e registrarBaixa, que grava o que a entidade já decidiu.

Sai contarNoAcervoDoAutor. Ela respondia “quantos livros deste autor estão no acervo?” com um COUNT(*) — e a resposta a essa pergunta acabou de mudar de significado. Manter a assinatura obrigaria o SQL a saber o que é “estar no acervo”, e essa decisão acabou de ganhar um dono: Livro.estaNoAcervo.

05

Aplicação · o cadastro passa a perguntar à entidade

Antes de escrever a fatia nova, conserte a antiga: o CadastrarLivro usava contarNoAcervoDoAutor, que não existe mais. Ele já buscava os livros do autor para conferir o título (RF09). Agora busca uma vez, filtra pelo que está no acervo e usa a mesma lista para as duas regras.

import type { NovoLivro } from "./input";
import { livroToJson, type LivroJson } from "../../output";

export class CadastrarLivro {
  constructor(
    private readonly livros: LivroRepository,
    private readonly autoria: ConsultaDeAutoria,
    private readonly now: Clock,
    private readonly events: EventPublisher,
  ) {}

  execute(input: NovoLivro): LivroJson {
    const isbn = new Isbn(input.isbn);
    const autorId = new AutorId(input.autorId);

    const autor = this.autoria.autor(autorId);

    if (!autor) {
      throw new NotFound("Autor não cadastrado");
    }

    // livro que já saiu do acervo não conta no limite nem bloqueia o título
    const noAcervo = this.livros
      .findByAutorId(autorId)
      .filter((livro) => livro.estaNoAcervo());

    LimiteDeLivros.verificar(autor.tiragem, noAcervo.length);

    if (this.livros.findByIsbn(isbn)) {
      throw new RuleConflict("Livro já cadastrado");
    }

    const mesmoTitulo = noAcervo.some((livro) =>
      livro.mesmoTituloQue(input.titulo),
    );

    if (mesmoTitulo) {
      throw new RuleConflict("Este autor já tem um livro com este título");
    }

    const hoje = this.now();
    const ano = toIso(hoje).slice(0, 4);

    const livro = this.livros.insert(
      Livro.catalogar(
        isbn,
        input.titulo,
        autorId,
        hoje,
        this.livros.contarCatalogadosNoAno(ano),
      ),
    );

    this.events.publish({
      nome: "LivroCatalogado",
      autorId: livro.autorId.value,
      numeroRegistro: livro.numeroRegistro.value,
      em: livro.dataCatalogacao,
    });

    return livroToJson(livro, autor);
  }

Aplicação · o caso de uso DarBaixa

Leia o corpo do execute como uma frase: monta o número de registro (o domínio confere o formato — RN2) e a baixa (o domínio confere o motivo e carimba a data do relógio — RN1 e RN3); procura o livro (RN2); manda a entidade sair do acervo (RN4); grava; anuncia (RN6).

  constructor(
    private readonly livros: LivroRepository,
    private readonly autoria: ConsultaDeAutoria,
    private readonly now: Clock,
    private readonly events: EventPublisher,
  ) {}

  execute(input: PedidoDeBaixa): LivroJson {
    const numero = new NumeroRegistro(input.numeroRegistro);
    const baixa = Baixa.registrar(input.motivo, this.now());

    const livro = this.livros.findByNumeroRegistro(numero);

    if (!livro) {
      throw new NotFound("Livro não encontrado");
    }

    const baixado = livro.darBaixa(baixa);

    this.livros.registrarBaixa(baixado);

    this.events.publish({
      nome: "LivroBaixado",
      autorId: baixado.autorId.value,
      numeroRegistro: baixado.numeroRegistro.value,
      motivo: baixa.motivo,
      em: baixa.em,
    });

    return livroToJson(baixado, this.autoria.autor(baixado.autorId)!);
  }
}
O construtor recebe as mesmas quatro portas do CadastrarLivro. A ConsultaDeAutoria está aí só por causa da resposta: o JSON do livro mostra o nome do autor e a contagem da projeção.
