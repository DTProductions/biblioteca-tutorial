02

Postgres 18, só na rede interna do Docker

O Postgres vai rodar num contêiner, sem instalar nada no Windows. O arquivo compose.yaml descreve os serviços do projeto. Por enquanto é um só: o banco.

O serviço db

Crie compose.yaml: na raiz do projeto, ao lado da pasta backend/

yamlcompose.yaml
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: biblioteca
      POSTGRES_PASSWORD: biblioteca
      POSTGRES_DB: biblioteca
    # sem "ports": o banco não fica exposto no seu computador, só os outros
    # serviços deste compose.yaml o enxergam, pela rede interna do Docker
    volumes:
      # a partir do Postgres 18 o volume é montado em /var/lib/postgresql
      # (e não mais em /var/lib/postgresql/data)
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -h localhost -U biblioteca -d biblioteca"]
      interval: 2s
      timeout: 3s
      retries: 15

volumes:
  pgdata:
  • image: postgres:18: a imagem oficial, baixada do Docker Hub na primeira vez.
  • environment: usuário, senha e banco que a imagem cria na primeira subida.
  • Não há ports, de propósito. Sem essa seção, nenhuma porta do seu computador leva ao banco. Ele só é alcançável por outros contêineres do mesmo compose.yaml, pela rede interna que o Docker cria para o projeto. Assim o banco não fica exposto e não briga com um PostgreSQL que já esteja instalado no Windows na porta 5432.
  • volumes: os dados ficam num volume com nome (pgdata), que sobrevive quando o contêiner é apagado e recriado.
  • healthcheck: o Docker pergunta periodicamente ao pg_isready se o banco já aceita conexões. O -h localhost faz a pergunta pela rede, como a aplicação fará; sem ele, a resposta pode vir positiva cedo demais na primeira subida, quando o Postgres ainda está se preparando. Vai ser útil no passo 05.
Novidade do Postgres 18. Até a versão 17, o volume era montado em /var/lib/postgresql/data. A imagem 18 guarda os dados em /var/lib/postgresql/18/docker e espera o volume em /var/lib/postgresql. Muito tutorial na internet ainda mostra o caminho antigo.

Suba o banco

Ainda na raiz do projeto (se estiver em backend/, volte com cd ..):

terminalPowerShell
docker compose up -d db
docker compose ps

Espere a coluna STATUS mostrar (healthy). Repare na coluna PORTS: aparece só 5432/tcp, sem um 0.0.0.0:5432-> na frente. A porta existe dentro da rede do Docker, mas não foi publicada no seu computador.

Mesmo sem porta, dá para conversar com o banco entrando no contêiner com docker compose exec, que roda o comando lá dentro:

terminalPowerShell
docker compose exec db psql -U biblioteca -d biblioteca -c "select version();"

Crie também um segundo banco, só para os testes. Assim os testes nunca apagam o que você cadastrou à mão:

terminalPowerShell
docker compose exec db createdb -U biblioteca biblioteca_test
O preço do isolamento. Como o banco não tem porta no seu computador, nenhum programa rodando no Windows chega até ele, nem o backend. Tudo o que fala com o banco vai rodar dentro de contêineres da mesma rede: a aplicação (passo 04) e os testes de integração (passo 05). O que não fala com banco continua rodando direto no Windows: o compilador, os testes de unidade e o frontend.
03

As ports viram assíncronas (ainda no SQLite)

O composition root promete, num comentário: “Trocar de banco é trocar as duas linhas de new Sqlite... daqui.” Hoje essa promessa vai ser cobrada, e ela não se cumpre de graça.

Todo cliente de Postgres em JavaScript é assíncrono: uma consulta devolve uma Promise, porque a resposta atravessa a rede. Já a port diz findByIsbn(isbn): Livro | null, ou seja, devolve o livro na hora. Nenhum adapter Postgres consegue cumprir esse contrato. Ele só parecia neutro porque o SQLite embutido no Bun responde de forma síncrona: a port vazou um detalhe do primeiro adapter.

A saída é mudar o contrato antes de trocar de banco, ainda no SQLite, com os testes como rede de proteção. Uma coisa de cada vez: primeiro a forma, depois a peça. Este passo inteiro roda no Windows, sem Docker.

import { sql } from "../../../infrastructure/postgres";
import { LivroId, AutorId } from "../../../shared/identifiers";
import { Isbn } from "../domain/Isbn";
import { Livro } from "../domain/Livro";
import type { LivroRepository } from "../domain/LivroRepository";
import { NumeroRegistro } from "../domain/NumeroRegistro";

type LivroRow = {
  id: number;
  numero_registro: string;
  isbn: string;
  titulo: string;
  autor_id: number;
  data_catalogacao: string;
};

function toLivro(row: LivroRow): Livro {
  return new Livro(
    new LivroId(row.id),
    new NumeroRegistro(row.numero_registro),
    new Isbn(row.isbn),
    row.titulo,
    new AutorId(row.autor_id),
    row.data_catalogacao,
  );
}

/**
 * Mesmo contrato do SqliteLivroRepository, outro banco. Os valores entram
 * pelo template `sql`...`` e viram parâmetros: nunca há concatenação de SQL.
 */
export class PostgresLivroRepository implements LivroRepository {
  async contarNoAcervoDoAutor(autorId: AutorId): Promise<number> {
    // COUNT devolve bigint, que chega como string; ::int faz chegar number
    const [row] = (await sql`
      SELECT COUNT(*)::int AS total FROM livros WHERE autor_id = ${autorId.value}
    `) as { total: number }[];

    return row!.total;
  }

  async contarCatalogadosNoAno(ano: string): Promise<number> {
    const [row] = (await sql`
      SELECT COUNT(*)::int AS total FROM livros
       WHERE data_catalogacao LIKE ${`${ano}%`}
    `) as { total: number }[];

    return row!.total;
  }

  async insert(livro: Livro): Promise<Livro> {
    const [row] = (await sql`
      INSERT INTO livros (numero_registro, isbn, titulo, autor_id, data_catalogacao)
      VALUES (${livro.numeroRegistro.value}, ${livro.isbn.value}, ${livro.titulo},
              ${livro.autorId.value}, ${livro.dataCatalogacao})
      RETURNING id
    `) as { id: number }[];

    return livro.withId(new LivroId(row!.id));
  }

  async findByIsbn(isbn: Isbn): Promise<Livro | null> {
    const [row] = (await sql`
      SELECT * FROM livros WHERE isbn = ${isbn.value}
    `) as LivroRow[];

    return row ? toLivro(row) : null;
  }

  async findByAutorId(autorId: AutorId): Promise<Livro[]> {
    const rows = (await sql`
      SELECT * FROM livros WHERE autor_id = ${autorId.value}
    `) as LivroRow[];

    return rows.map(toLivro);
  }

  async searchByTitulo(termo: string): Promise<Livro[]> {
    // no SQLite, LIKE ignora maiúsculas; no Postgres, não. ILIKE mantém o contrato
    const rows = (await sql`
      SELECT * FROM livros WHERE titulo ILIKE ${`%${termo}%`}
    `) as LivroRow[];

    return rows.map(toLivro);
  }

  async findByAutorIds(autorIds: AutorId[]): Promise<Livro[]> {
    if (autorIds.length === 0) return [];

    const ids = autorIds.map((autorId) => autorId.value);
    const rows = (await sql`
      SELECT * FROM livros WHERE autor_id IN ${sql(ids)}
    `) as LivroRow[];

    return rows.map(toLivro);
  }
}
  • Parâmetros, não concatenação. No template sql`...${valor}...`, cada ${} vira um parâmetro da consulta ($1, $2…). O texto nunca é colado no SQL, e por isso não há injeção. É o papel que os ? tinham no SQLite.
  • COUNT(*)::int. No Postgres, COUNT devolve bigint, e o Bun entrega bigint como string ("5") para não perder precisão. Com o ::int, chega um number, como o contrato exige.
  • ILIKE. No SQLite, LIKE ignora maiúsculas e minúsculas; no Postgres, não. Com LIKE, buscar “domain” deixaria de achar “Domain-Driven Design”: o código compilaria e o contrato estaria quebrado. Mesmo contrato significa mesmo comportamento, não só mesma assinatura.
  • IN ${sql(ids)}. O sql(lista) expande a lista em ($1, $2, …).

/** O que a API devolve para cada livro (o LivroJson do backend). */
export type Livro = {
  id: number;
  numeroRegistro: string;
  isbn: string;
  titulo: string;
  autor: string;
  livrosDoAutor: number;
  dataCatalogacao: string;
};

/** O que a API espera para cadastrar um livro. */
export type NovoLivro = {
  isbn: string;
  titulo: string;
  autorId: number;
};

/** Lê o JSON da resposta. Se a API recusou, lança o { error } que ela mandou. */
async function lerJson<T>(resposta: Response): Promise<T> {
  const corpo = await resposta.json().catch(() => ({}));

  if (!resposta.ok) {
    throw new Error(corpo.error ?? `Erro ${resposta.status}`);
  }

  return corpo as T;
}

export async function buscarLivros(termo: string): Promise<Livro[]> {
  const resposta = await fetch(`/api/livros/${encodeURIComponent(termo)}`);

  return lerJson<Livro[]>(resposta);
}

export async function cadastrarLivro(livro: NovoLivro): Promise<Livro> {
  const resposta = await fetch("/api/livros", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(livro),
  });

  return lerJson<Livro>(resposta);
}

/** "2026-10-01" → "01/10/2026", sem passar por Date (e sem erro de fuso). */
export function formatarData(iso: string): string {
  return iso.split("-").reverse().join("/");
}

O lerJson transforma qualquer resposta de erro da API (400, 404, 409) numa exceção com a mensagem que o backend mandou, como “Livro já cadastrado” ou “O autor já tem 5 livros no acervo”.

4 · A página de busca

Crie frontend/src/pages/BuscarLivros.tsx:

tsxfrontend/src/pages/BuscarLivros.tsx
import { useEffect, useState, type FormEvent } from "react";
import { useSearchParams } from "react-router-dom";
import { buscarLivros, formatarData, type Livro } from "../api.ts";

/** A resposta da API, junto com o termo que a produziu. */
type Resultado = {
  termo: string;
  livros: Livro[];
  erro: string;
};

export default function BuscarLivros() {
  // o termo mora na URL (/?q=...): recarregar a página repete a busca
  const [params, setParams] = useSearchParams();
  const termo = params.get("q") ?? "";

  const [resultado, setResultado] = useState<Resultado | null>(null);

  useEffect(() => {
    if (termo === "") return;

    // se o termo mudar antes da resposta chegar, a resposta antiga é ignorada
    let ignorar = false;

    buscarLivros(termo)
      .then((livros) => {
        if (!ignorar) setResultado({ termo, livros, erro: "" });
      })
      .catch((e: Error) => {
        if (!ignorar) setResultado({ termo, livros: [], erro: e.message });
      });

    return () => {
      ignorar = true;
    };
  }, [termo]);

  // ainda não chegou resposta para o termo que está na URL
  const carregando = resultado?.termo !== termo;

  function buscar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();

    const q = String(new FormData(evento.currentTarget).get("q")).trim();

    setParams(q === "" ? {} : { q });
  }

  return (
    <section>
      {/* React 19: <title> dentro do componente vai parar no <head> */}
      <title>Buscar livros · Biblioteca</title>

      <h1>Buscar livros</h1>

      <form className="busca" onSubmit={buscar}>
        <input
          // key: quando a URL muda (menu, voltar), o campo recomeça com o termo dela
          key={termo}
          name="q"
          defaultValue={termo}
          placeholder="ISBN, título ou nome do autor"
          aria-label="Termo de busca"
        />
        <button type="submit">Buscar</button>
      </form>

      {termo === "" ? (
        <p className="dica">Digite um ISBN, parte do título ou o nome do autor.</p>
      ) : carregando ? (
        <p className="dica">Buscando…</p>
      ) : resultado.erro !== "" ? (
        <p className="erro">{resultado.erro}</p>
      ) : resultado.livros.length === 0 ? (
        <p className="dica">Nenhum livro encontrado para “{termo}”.</p>
      ) : (
        <table>
          <thead>
            <tr>
              <th>Registro</th>
              <th>ISBN</th>
              <th>Título</th>
              <th>Autor</th>
              <th>Catalogado em</th>
            </tr>
          </thead>
          <tbody>
            {resultado.livros.map((livro) => (
              <tr key={livro.id}>
                <td>{livro.numeroRegistro}</td>
                <td>{livro.isbn}</td>
                <td>{livro.titulo}</td>
                <td>{livro.autor}</td>
                <td>{formatarData(livro.dataCatalogacao)}</td>
              </tr>
            ))}
          </tbody>
        </table>
      )}
    </section>
  );
}
  • O termo mora na URL (/?q=evans), via useSearchParams. Recarregar a página, voltar no navegador ou mandar o link para alguém repete a mesma busca.
  • Um estado só. O resultado guarda de qual termo ele é. Se não é do termo atual, a busca ainda está em andamento: o “carregando” é calculado, não guardado num segundo estado.
  • ignorar. Se o usuário busca “a” e logo depois “ab”, a resposta de “a” pode chegar por último. A limpeza do useEffect descarta respostas velhas.
  • <title> dentro do componente é novidade do React 19: ele é levado para o <head> e muda o título da aba.

import { Hono } from "hono";
import { serveStatic } from "hono/bun";
import type { UseCases } from "./composition";
import { DomainError, InvalidValue } from "./shared/domain-errors";
import { registerRoutes as registerAcervo } from "./modules/acervo";
import { InvalidInput, NotFound, RuleConflict } from "./shared/errors";

/** O build do React (`bun run build` em frontend/), relativo à pasta backend/. */
const FRONTEND = "../frontend/dist";

function errorResponse(error: unknown): Response {
  if (error instanceof InvalidInput || error instanceof InvalidValue) {
    return Response.json({ error: error.message }, { status: 400 });
  }

  if (error instanceof NotFound) {
    return Response.json({ error: error.message }, { status: 404 });
  }

  if (error instanceof RuleConflict || error instanceof DomainError) {
    return Response.json({ error: error.message }, { status: 409 });
  }

  console.error(error);

  return Response.json({ error: "Erro interno" }, { status: 500 });
}

export function createServer(useCases: UseCases, porta = Number(process.env.PORT ?? 3000)) {
  const api = new Hono();

  api.get("/", (contexto) => contexto.json({ message: "API da Biblioteca" }));

  registerAcervo(api, useCases);

  const app = new Hono();

  // toda a API mora sob /api: o resto dos endereços fica livre para o frontend
  app.route("/api", api);
  app.all("/api/*", (contexto) => contexto.notFound());

  // arquivos do build: index.html, JS, CSS, ícone
  app.use("*", serveStatic({ root: FRONTEND }));

  // qualquer outro endereço (/cadastrar, por exemplo) é rota do React Router:
  // devolve o index.html e o roteador do navegador decide o que mostrar
  app.get("*", serveStatic({ path: `${FRONTEND}/index.html` }));

  app.notFound((contexto) =>
    contexto.json({ error: "Recurso não encontrado" }, 404),
  );

  app.onError((error) => errorResponse(error));
